# Phase 5 — UI Design Contract

> Visual and interaction contract for the File Sharing phase. Extends Phase 3 design system — do NOT re-declare tokens that already exist in `client/src/styles/tokens.css`. This document adds only what Phase 5 introduces.
> Generated by gsd-ui-researcher. Consumed by gsd-ui-checker, gsd-planner, gsd-executor, and gsd-ui-auditor.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled components, same as Phase 3 |

## Layout Contract

All existing layouts are inherited unchanged. Phase 5 adds these new surfaces:

### 1. Drag-Over Overlay

Applied to the `MessageInput` container (and MessageList area above it) when `dragover` event fires on the window.

```
┌─ MessageList (flex: 1) ─────────────────────────────┐
│                                                       │
│  [existing messages]                                  │
│                                                       │
│  ┌─ Drop zone highlight ───────────────────────────┐  │
│  │  2px dashed var(--color-accent)                 │  │
│  │  border-radius: 8px                             │  │
│  │  background: rgba(11, 87, 208, 0.04)            │  │
│  └─────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────┘
```

- The dashed border and tint overlay are applied via a CSS class toggled in React state on `dragenter`/`dragleave`/`drop`
- Only the bottom portion (MessageInput + nearby MessageList) gets the visual; the full-pane tint keeps it non-intrusive
- No text label inside the drop zone (the visual feedback alone is sufficient)

### 2. Upload Progress Strip (above textarea)

Inserted between any reply/edit strip and the textarea row. Hidden when no upload is in progress.

```
┌─ InputArea ──────────────────────────────────────────┐
│ ┌─ [Reply/Edit strip — if active] ─────────────────┐ │
│ └───────────────────────────────────────────────────┘ │
│ ┌─ Upload strip ────────────────────────────────────┐ │
│ │ [thumb 48×48] [filename  ···  size]     [× cancel]│ │
│ │ [━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 67%]               │ │
│ └───────────────────────────────────────────────────┘ │
│ ┌─ Row ─────────────────────────────────────────────┐ │
│ │ [📎] [textarea]                        [Send btn] │ │
│ └───────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────┘
```

- Strip background: `--color-surface-secondary`
- Strip top border: `1px solid var(--color-border)`
- Strip padding: `--space-sm` vertical, `--space-md` horizontal
- Thumbnail: 48×48px, `border-radius: 4px`, `object-fit: cover` (images); 32×32px file icon (non-images)
- Progress bar: full width minus padding; height 4px; track `--color-accent-muted`; fill `--color-accent`; `border-radius: 2px`
- Cancel (×) button: `--text-label` size, `--color-text-muted` color, hover `--color-text-primary`, no background, `aria-label="Cancel upload"`
- **After upload completes (ready to send state):** progress bar replaced by a green checkmark (✓ in `--color-success`). Filename and thumbnail remain. × button remains for removing before send.

### 3. Upload Error State (in input area)

Appears below the upload strip (or below the textarea row if no strip is showing) when upload fails.

```
┌─ Error row ───────────────────────────────────────────┐
│ ⚠ Upload failed: file too large (25 MB max)  [Retry] │
└───────────────────────────────────────────────────────┘
```

- Text: `--text-label` size, `--color-destructive`
- Retry button: text-only button, `--color-accent`, no background, underline on hover
- Clears on successful upload or on user dismissal

- `<img>` uses `width`/`height` attributes (from thumbnail dimensions) to reserve space and prevent layout shift
- Loading placeholder: `background: var(--color-surface-secondary)` block (solid color, no spinner) until image loads

## Interaction Contracts

### File Selection

- Paperclip button (left of textarea): 40×40px touch target, `aria-label="Attach file"`. Click triggers `fileInputRef.current.click()` on a hidden `<input type="file">` element.
- Hidden file input: `accept` defaults to `*/*` (all files allowed, server validates). `type="file"`. Hidden via `display: none`.
- Drag-and-drop: `dragenter` on `window` sets `isDragging: true` state. `dragleave` on `window` (only when `relatedTarget` is null — leaving the window entirely) sets `isDragging: false`. `drop` on the drop zone captures `e.dataTransfer.files[0]` and begins upload.
- Both paths lead to the same `handleFileSelect(file: File)` function.
- If a file is already staged (upload in progress or ready-to-send), a second selection replaces the first after confirming cancellation of the current upload.

### Upload Flow (two-step as per CONTEXT.md D-19)

1. `handleFileSelect` → client-side size check: if `file.size > 25 * 1024 * 1024` → show error immediately, no XHR
2. If size OK → show `UploadStrip` with 0% progress, issue XHR `POST /api/files`
3. XHR `progress` event → update progress bar (0–99%)
4. XHR `load` with 200 → set strip to "ready-to-send" state (progress replaced by ✓)
5. XHR `load` with 4xx/5xx → show error message, strip transitions to error state
6. XHR `abort` (cancel button) → hide strip, reset state
7. On send (Enter or Send button): if `file_id` is set, include `file_id` in `message:send` WS payload. Upload strip clears on successful send WS ack.

### Send Button State with File Attached

- When a file is ready-to-send: Send button is **enabled** regardless of textarea content (caption is optional per CONTEXT.md D-19)
- When upload is in progress: Send button is **disabled** (user must wait for upload to complete)
- When upload errored: Send button is **disabled**

### Paperclip Button Visibility

- The paperclip button is always visible in the textarea row, left of the textarea. It does not toggle or disappear.
- Disabled (greyed) when an upload is already in progress.

### Lightbox Interaction

- Open: click on inline image thumbnail within a message bubble
- Dismiss: Escape key, backdrop click, or × button click
- Transition: opacity `0 → 1` in 150ms on open; `1 → 0` in 150ms on close before unmounting (use CSS transition + React state `isVisible` with delayed unmount)
- Focus: on open, focus moves to the close button (`aria-label="Close image viewer"`)
- Focus trap: Tab cycles only between close button and image (image receives `tabIndex={0}`)
- Image loading: show spinner while `<img>` is loading; hide spinner and show image when `onLoad` fires

### Download (File Card)

- Click on download button OR full card → `window.location.href = '/api/files/' + fileId` — browser handles download via `Content-Disposition: attachment` header from server
- No JavaScript blob download — rely on browser native behavior

### Avatar Upload (GroupSettingsModal)

- Click on avatar area (admin only) → hidden file input click
- Accepts only `image/*` (client-side filter on file input `accept` attribute)
- Same XHR progress strip shown in the modal while uploading
- On success: call `PATCH /api/conversations/:id` with `{ avatar_url: '/api/files/<fileId>' }` then close upload UI
- On error: show error text in modal, no retry auto-trigger

### Drag-Over Visual

- Activate class on `dragenter` (first file enters the browser window)
- Deactivate class on `dragleave` where `event.relatedTarget === null` (cursor left window, not just moved between DOM elements)
- Deactivate on `drop` always
- Border style: `2px dashed var(--color-accent)` applied to the MessageInput container
- Background tint: `background: rgba(11, 87, 208, 0.04)` on the same container
- No text label inside the zone

## File Icon Contract

`FileIcon` component renders an inline SVG based on MIME prefix. No external library.

| MIME Prefix / Type | Icon Description | SVG Approach |
|--------------------|-----------------|--------------|
| `image/*` | (not used — images render as thumbnails) | — |
| `application/pdf` | Rectangle with folded corner + "PDF" text | Inline SVG, red accent (#c5221f — destructive token) |
| `video/*` | Play triangle inside rounded rectangle | Inline SVG, neutral `--color-text-secondary` |
| `audio/*` | Musical note or waveform bars | Inline SVG, neutral `--color-text-secondary` |
| `application/zip`, `application/x-rar-compressed`, `application/x-7z-compressed` | Box with down-arrow | Inline SVG, neutral `--color-text-secondary` |
| all others (generic) | Document icon (rectangle with top-right fold) | Inline SVG, neutral `--color-text-secondary` |

All icons: 32×32px viewBox, `aria-hidden="true"`, no labels (filename provides context). Stroke-based, weight 1.5px, no fill.

## Avatar Component Extension Contract

The `Avatar` component in `client/src/components/common/Avatar.tsx` receives a new optional prop:

```
interface AvatarProps {
  name: string;
  size?: 'sm' | 'md' | 'lg';
  avatarUrl?: string | null;   // NEW in Phase 5
}
```

Rendering logic:
1. If `avatarUrl` is a non-empty string → render `<img src={avatarUrl} alt={name} className={styles.avatar} />`
2. Else → render existing initials circle (unchanged behavior)

The `<img>` element uses the same size classes (`sm`, `md`, `lg`) as the initials circle. `object-fit: cover`. `border-radius: 50%`. On `onError`: fall back to initials rendering (set local state `imgError: true`).

## Accessibility Contract (Phase 5 additions)

- Lightbox: `role="dialog"`, `aria-modal="true"`, `aria-label="Image viewer"`. Focus on close button on open. Focus returns to the image thumbnail that triggered it on close.
- File card download button: `<button>` element with `aria-label="Download [filename]"`.

## State Management Contract

Phase 5 adds upload state to `MessageInput` only (local component state, not lifted to `ChatContext`):

```typescript
type UploadState =
  | { status: 'idle' }
  | { status: 'uploading'; file: File; progress: number; abortController: AbortController }
  | { status: 'ready'; file: File; fileId: string; thumbnailUrl?: string }
  | { status: 'error'; file: File; message: string };
```

- `ChatContext` is NOT extended for upload state (local to input component)
- Lightbox state (`isOpen`, `imageUrl`) is local to `MessageItem` or lifted to a `LightboxContext` only if multiple images in same view need coordination — for v1, local to each `MessageItem` is sufficient
- Avatar upload state in `GroupSettingsModal` is local component state (mirrors the UploadState shape above)
