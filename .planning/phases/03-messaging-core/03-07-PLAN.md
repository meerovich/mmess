Two targeted edits in the handleIncoming switch statement.

**Fix 1 — typing:user (lines 77-96):**
Replace the entire typing:user case body. The current code reads `msg.payload.is_typing`, `msg.payload.user_id`, `msg.payload.username` (scalar fields that don't exist). The server sends `{ conversation_id, typers: [{userId, username}[]}`.

Replace the case with:
```typescript
case 'typing:user':
  if (msg.payload?.conversation_id) {
    dispatch({
      type: 'SET_TYPING_USERS',
      conversationId: msg.payload.conversation_id as string,
      typers: (msg.payload.typers as { userId: string; username: string }[]) ?? [],
    });
  }
  break;
```

**Fix 2 — conversation:new (lines 106-113):**
The current code checks `msg.payload?.conversation` but the server broadcasts the conversation object directly as `msg.payload`. Change:

```typescript
case 'conversation:new':
  if (msg.payload?.conversation) {
    dispatch({
      type: 'UPSERT_CONVERSATION',
      conversation: msg.payload.conversation as import('../types/chat').Conversation,
    });
  }
  break;
```

to:

```typescript
case 'conversation:new':
  if (msg.payload) {
    dispatch({
      type: 'UPSERT_CONVERSATION',
      conversation: msg.payload as unknown as import('../types/chat').Conversation,
    });
  }
  break;
```
