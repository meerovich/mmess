**MessageList.tsx** — scroll container + infinite load + auto-scroll:

Props: `{ conversationId: string }`.

Uses `useChat()` for `state.messages[conversationId]`.

Local state: `isLoadingMore: boolean`.

Maintains: `listRef = useRef<HTMLDivElement>(null)`.

Sentinel div at TOP of list observed by IntersectionObserver. When sentinel visible AND `hasMore` AND not loading:
1. Save `prevScrollHeight`
2. `dispatch({ type: 'PREPEND_MESSAGES', ... })` after calling `apiFetch` with `before=nextCursor`
3. After React re-render: `requestAnimationFrame` to restore scroll position using `scrollHeight` delta

Auto-scroll to bottom on new message: use `useEffect` watching messages array length. Only scroll if `isAtBottom()`:
```typescript
const isAtBottom = () => {
  if (!listRef.current) return false;
  const { scrollTop, scrollHeight, clientHeight } = listRef.current;
  return scrollHeight - scrollTop - clientHeight < 100;
};
```

On initial load (when `activeConversationId` changes): fetch `GET /api/conversations/${conversationId}/messages?limit=50` via `apiFetch`, dispatch `SET_MESSAGES`, then scroll to bottom.

Render each message as `<MessageItem key={msg.id} message={msg} />`. Group consecutive messages from same sender (within 5 min) — pass `isGrouped: boolean` prop to MessageItem to reduce avatar/spacing.

**MessageInput.tsx** — textarea + send + strips:

Props: `{ conversationId: string }`.

Local state:
- `value: string` — textarea content
- `replyTo: Message | null` — active reply target
- `editMessage: Message | null` — active edit target

Uses `useSendMessage()`, `useAuth()` (for sender_id), `useChat()` (for dispatch and currentUserId).

**Typing indicator (D-34):**
- On each keystroke: if first non-empty keystroke → `sendWs({ type: 'typing:start', payload: { conversation_id } })`
- Debounce 3s reset: setTimeout that sends `typing:stop` after 3s of no keystrokes (clear on each keystroke)
- On input empty: immediate `sendWs({ type: 'typing:stop', payload: { conversation_id } })`
- On unmount: send `typing:stop`

**Send message (D-03, optimistic UI Pattern 4):**
- Enter (no Shift) submits if `value.trim().length > 0`
- On send:
  1. Generate `tempId = nanoid()`
  2. Build optimistic message: `{ id: tempId, content: value.trim(), sender_id: currentUserId, reply_to_id: replyTo?.id ?? null, status: 'sending', ... }`
  3. Dispatch `OPTIMISTIC_MESSAGE_ADD`
  4. `sendWs({ type: 'message:send', id: tempId, payload: { conversation_id: conversationId, content: value.trim(), reply_to_id: replyTo?.id } })`
  5. Reset `value = ''`, `replyTo = null`, refocus textarea

**Reply strip**: when `replyTo` is set → render strip above textarea: `"↩ Replying to [Name]:"` + first 80 chars of content + × button to cancel. Background `--color-surface-secondary`, padding `--space-xs --space-md`.

**Edit strip + Edit flow**: when `editMessage` is set → strip: `"✏ Editing message"` + × to cancel. Textarea pre-filled with `editMessage.content`. Send button shows "Save changes". On submit: `sendWs({ type: 'message:edit', payload: { message_id: editMessage.id, content: value.trim() } })`. Clear `editMessage`, reset textarea.

To receive `onEdit` from MessageItem, use a context or pass via ChatPane. Simpler: create a `EditContext` (local) inside ChatPane that MessageItem writes to and MessageInput reads from. Alternatively: lift `editMessage` state to ChatPane and pass as props.

**Send button**: disabled when `value.trim().length === 0`. `aria-label="Send message"`. Background `--color-accent` when active.

**Emoji picker trigger**: `[+]` button with `aria-label="Add reaction"` — actually on message hover (this is in ReactionBar, not MessageInput). MessageInput has the send button only; emoji for reactions lives in ReactionBar's [+] button.
