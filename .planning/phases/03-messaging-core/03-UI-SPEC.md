# Phase 3 — UI Design Contract

> Visual and interaction contract for the Messaging Core phase. Generated by gsd-ui-researcher.
> Consumed by gsd-ui-checker, gsd-planner, gsd-executor, and gsd-ui-auditor.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled components |
| Icon library | none in Phase 3 — Unicode characters for check marks (✓ ✓✓), inline SVG for send button only |
| Font | system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif |

**Rationale (designer discretion):** No shadcn or Tailwind is introduced in Phase 3. Reasons: (1) Phase 2 is pure inline styles — zero CSS infrastructure exists; (2) Phase 6 is dedicated to "polished, responsive interface" and is the correct time for a full design-system migration; (3) the project is a personal messenger where functional over-polish is the explicit value. Phase 3 uses **CSS Modules** (`*.module.css`) with **CSS custom properties** for all tokens, making it trivially theme-ready for Phase 6's dark/light toggle without a rewrite.

**Token file:** `client/src/styles/tokens.css` — imported once in `main.tsx`, declares all `:root` custom properties. Every component references only `var(--token-name)`, never raw values.

Declared values (multiples of 4):

| Token | CSS Variable | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--space-xs` | 4px | Icon gaps, reaction badge inner padding, check mark gap |
| sm | `--space-sm` | 8px | Input field inner padding (vertical), message bubble inner padding (vertical), sidebar item gap |
| md | `--space-md` | 16px | Message bubble inner padding (horizontal), sidebar item padding, modal padding |
| lg | `--space-lg` | 24px | Sidebar header padding, chat header padding, section breaks |
| xl | `--space-xl` | 32px | Chat pane horizontal padding on wide viewports |
| 2xl | `--space-2xl` | 48px | Not used in Phase 3 |
| 3xl | `--space-3xl` | 64px | Not used in Phase 3 |

Exceptions:
- Sidebar width: 280px fixed (not a spacing token — it is a layout dimension token `--sidebar-width: 280px`)
- Touch targets on mobile: minimum 44px height for all interactive elements (accessibility floor, not a spacing token)
- Message input min-height: 44px (matches touch target floor)
- Unread badge min-width: 20px, height 20px (circular at single digit; pill at 2+ digits)
- Online presence dot: 10px × 10px (positioned absolute, 2px border matching surface)

- Sidebar: `width: var(--sidebar-width)` (280px), `flex-shrink: 0`, `overflow-y: auto`

- Message list: `flex: 1`, `overflow-y: auto`, `display: flex`, `flex-direction: column-reverse` (newest at bottom, scroll up for history)
- No horizontal scrollbar at any viewport width

### Mobile (< 768px): Single-pane navigation

- Sidebar fills 100vw. Chat pane is hidden.
- Tapping a conversation hides sidebar, shows chat pane (100vw).
- Chat pane header has a back button (`←`) — left of avatar/name — that returns to sidebar.
- Use CSS `display: none` toggled by a React state boolean `showChat`. No router navigation change.

## Interaction Contracts

### Message Sending
- Send button active only when `textarea.value.trim().length > 0`
- Pressing Enter (without Shift) submits the message; Shift+Enter inserts newline
- On send: message appears immediately in optimistic state (greyed send indicator); confirmed on `ack` WS message
- Textarea resets to empty after send; focus returns to textarea

### Infinite Upward Scroll (MSG-03)
- Initial load: 50 most recent messages (source: CONTEXT.md D-13)
- Load more trigger: `IntersectionObserver` on a sentinel `div` at the top of `MessageList`
- When sentinel is visible AND more messages exist: dispatch `history:request` WS message with `before` cursor
- Loading older messages: prepend to list; do NOT reset scroll position (preserve user's reading position)
- Auto-scroll to bottom: ONLY when user is already at bottom (within 100px of bottom). Never yank scroll while user is reading history.

### Typing Indicator (MSG-04)
- `typing:start` sent on first keystroke in non-empty input
- Debounce timer: 3 seconds reset on each keystroke
- `typing:stop` sent when input becomes empty OR after 5 seconds idle without keystroke
- Display: single typer → `"Alice is typing…"`; two typers → `"Alice and Bob are typing…"`; 3+ typers → `"Several people are typing…"`
- Typing indicator area: fixed 20px height below message list, always present (prevents layout shift)

### Read Receipts (MSG-05) — WhatsApp style
- Single check (✓): message delivered to server (ack received)
- Double check (✓✓): message read by recipient(s)
  - In DM: double check when the other participant has read
  - In group: double check when ALL participants have read
- Double check color: grey (`--color-text-muted`) until all-read; then green (`--color-success`) when all-read
- Hover on double check (desktop): tooltip showing "Read by [Name] at [HH:MM], [Name2] at [HH:MM]" (source: D-32)
- Read receipt check marks render only on own messages (right-aligned bubbles)

### Reactions (MSG-10)
- Reactions row renders below message bubble when ≥ 1 reaction exists; hidden otherwise
- Badge format: `[emoji] [count]` e.g. `👍 3`
- Clicking a badge toggles own reaction (add if not reacted, remove if already reacted)
- Clicking `[+]` button (visible on message hover) opens emoji-mart picker
- Emoji picker: positioned above the message, closes on outside click or Escape
- Hover on badge: tooltip showing "Alice, Bob, Carol" (comma-separated list of reactor display names)
- Active reaction badge (current user reacted): `background: var(--color-reaction-bg-active)`

### Reply-to (MSG-09)
- Right-click or hover menu on any message exposes "Reply" action
- Clicking "Reply" activates reply mode: a strip above the textarea shows `↩ Replying to [Name]: [first 80 chars]` with an × to cancel
- Message sent in reply mode includes `reply_to_id`
- In message list, replied-to message renders a quote block above the content: left-border `3px solid var(--color-accent)`, sender name in `--text-label` heading weight, preview text in `--text-label` muted

### Edit/Delete (MSG-07, MSG-08)
- Hover a message (own message only, if permissions allow) → `···` overflow menu appears top-right of bubble
- Menu items: "Edit", "Delete"
- Direct chats: no edit/delete menu rendered at all (D-21)
- Group chats: menu appears only if `can_edit_messages: true` for current user
- **Edit flow:** Clicking "Edit" replaces the textarea content with the message text and activates edit mode. A strip above the textarea shows `✏ Editing message` with × to cancel. Send button label changes to "Save". On confirm, WS `message:edit` sent. Message re-renders with updated content + "(edited)" suffix.
- **Delete flow:** Clicking "Delete" shows an inline confirmation: `[Cancel] [Delete message]` (no modal). On confirm, WS `message:delete` sent. Message renders "Message deleted" placeholder.
- Edited message: `(edited)` rendered as `--text-label` italic muted text inline after timestamp
- Deleted message: full message bubble replaced with italic muted text "Message deleted"; no edit/delete menu

### Conversation Creation (CONV-01, CONV-02)
- "New DM" button (sidebar header): opens `NewChatModal`
  - Search input: `GET /api/users?q=…&limit=20` on each keystroke (debounced 300ms)
  - Results list: avatar + display name; clicking starts/opens DM
  - Modal closes on start or outside click or Escape
- "New Group" button (sidebar header): opens `NewGroupModal`
  - Group name text input (required, max 100 chars)
  - Multi-select user search (same search API); selected users shown as removable chips
  - "Create group" button: disabled until name non-empty AND ≥ 1 participant selected
  - On success: modal closes, new conversation is selected in sidebar

### Unread Count (MSG-06)
- Unread badge visible on sidebar item when `unread_count > 0`
- Display: 1–99 shown as number; 99+ shown as "99+" (source: CONTEXT.md D-11)
- Badge hidden (not just 0) when `unread_count === 0`

### WebSocket Reconnect
- On disconnect: show a non-blocking banner at top of chat pane: "Reconnecting…" (yellow background `#fdd663`, dark text)
- Retry every 5 seconds (fixed interval, D-05)
- Banner disappears immediately on successful reconnect
- On reconnect: client dispatches `history:request` per active conversation to catch missed messages (D-06)

- Other bubble: `background: var(--color-bubble-other)`, `border: 1px solid var(--color-border)`
- Consecutive messages from same sender (within 5 min): reduce vertical gap to 2px (vs 8px for new sender group)
- Timestamp: right-aligned inside bubble, `--text-label`, `--color-text-secondary`

## State Management Contract

Source: CONTEXT.md (Claude's Discretion).

**Decision:** Use **React Context + useReducer** for global chat state (no Zustand in Phase 3).

Rationale: Zustand adds a dependency and introduces patterns that differ from Phase 2's Context approach. For Phase 3's scope (one active conversation at a time, one conversation list), a `ChatContext` + `useReducer` is sufficient and consistent with existing `AuthContext` patterns. Phase 6 or beyond can migrate to Zustand if state complexity warrants it.

State shape:
- `conversations: Conversation[]` — sidebar list
- `activeConversationId: string | null`
- `messages: Record<conversationId, Message[]>` — per-conversation message cache
- `typingUsers: Record<conversationId, { userId: string; username: string }[]>`
- `wsStatus: 'connected' | 'disconnected' | 'reconnecting'`

WebSocket instance: held in a `useRef` inside `WebSocketProvider`, not in React state (prevents re-renders on message receipt).

## Emoji Library Contract

Source: CONTEXT.md D-27 (Claude's Discretion for specific library).

**Decision:** Use `@emoji-mart/react` + `@emoji-mart/data`.

- Package: `emoji-mart` v5.x — lightweight, tree-shakeable, framework-agnostic data
- Import picker lazily (`React.lazy`) to keep initial bundle lean
- Picker triggers: `[+]` button on message hover. Positioned with `position: absolute`, `bottom: 100%`, closes on `blur` or outside click
- On emoji select: dispatch `reaction:add` WS message with `{ message_id, emoji: native }`
- No custom emoji sets; use default `@emoji-mart/data`

## Date Formatting Contract

Source: Claude's Discretion.

**Decision:** Use `date-fns` for timestamp formatting.

- Message timestamp: `format(date, 'HH:mm')` — always 24-hour time, no AM/PM
- Sidebar last-activity: relative if < 24h ago (`formatDistanceToNow` with `addSuffix: false` → "5 min", "2 hr"), else `format(date, 'dd/MM')` for this calendar year, else `format(date, 'dd/MM/yy')`
- Read receipt tooltip: `format(date, 'HH:mm')` per user
- No i18n in Phase 3; locale hardcoded to `en-GB` for `date-fns`

## Accessibility Baseline

Minimum requirements for Phase 3 (full a11y audit in Phase 6):

- All interactive elements reachable via Tab in logical document order
- Send button has `aria-label="Send message"`
- Emoji picker trigger has `aria-label="Add reaction"`
- Message input has `aria-label="Message [ConversationName]"` (dynamic)
- Delete/edit menu items are `<button>` elements, not divs
- Modal dialogs use `role="dialog"` with `aria-modal="true"` and `aria-labelledby`
- Focus trap inside open modals (Tab cycles within modal)
- Escape closes any open modal or picker
- Unread badge: `aria-label="[N] unread messages"` on the ConversationItem
