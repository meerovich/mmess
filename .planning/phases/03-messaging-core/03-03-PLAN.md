**server/src/routes/conversations/index.ts** — GET /api/conversations

Returns all conversations for the authenticated user, sorted by most recent activity (D-12). Each conversation includes:
- Conversation fields (id, type, name)
- Last message: `{ id, content, sender_id, created_at }` (join via last_message_id)
- Unread count: `COUNT(*) WHERE messages.conversation_id = X AND messages.id > last_read_message_id` — use the participant's `last_read_message_id` as cursor (D-33). If last_read_message_id is null, count all messages in the conversation.
- Participants: array of `{ user_id, username, avatar_url }` (for DM name derivation on client; for groups the name field is set)
- For DMs: `name` field in response should be the OTHER participant's username (derive server-side)

Implementation approach:
```typescript
// Pseudocode — implement in Drizzle:
// 1. Get all conversations where user is a participant
// 2. For each: join last message, count unread, get participants
// Use a single query with LEFT JOINs where possible, or N+1 with batching

// Simplified approach (correct for small user base):
const userConversations = await db
  .select({ cp: conversation_participants, c: conversations })
  .from(conversation_participants)
  .innerJoin(conversations, eq(conversation_participants.conversation_id, conversations.id))
  .where(eq(conversation_participants.user_id, userId))
  .orderBy(desc(conversations.updated_at));  // updated_at changes on new message (D-12)
```

For each conversation, fetch:
- Last message via `conversations.last_message_id` (separate query or subquery)
- Unread count via `COUNT(*) FROM messages WHERE conversation_id = ? AND created_at > (SELECT created_at FROM messages WHERE id = last_read_message_id)` — or simpler: use a subquery
- Other participants (for DM name + avatars)

Return array sorted by `conversations.updated_at DESC`.

**server/src/routes/conversations/messages.ts** — GET /api/conversations/:id/messages

Implements cursor-based pagination exactly as RESEARCH.md Pattern 3.

Query params: `before` (cursor string, optional), `limit` (default 50, max 50).

Verify the requesting user is a participant before returning messages.

Include reactions for each message. Join `message_reactions` grouped by `message_id`.

Return format:
```typescript
{
  messages: Array<{
    id: string;
    conversation_id: string;
    sender_id: string;
    content: string | null;
    reply_to_id: string | null;
    is_deleted: boolean;
    edited_at: string | null;
    created_at: string;
    sender: { id: string; username: string; avatar_url: string | null };
    reply_to: { id: string; sender_id: string; content: string | null } | null;
    reactions: Array<{ emoji: string; user_id: string; username: string }>;
  }>;
  nextCursor: string | null;
  hasMore: boolean;
}
```

Cursor decode: `const [cursorDateStr, cursorId] = before.split('|')`. `cursorDate = new Date(cursorDateStr)`.

Messages in response must be ordered OLDEST FIRST (reverse the DESC query result before returning).

Include the message sender's `username` and `avatar_url` in the response (join with users table).

Include the `reply_to` message content and sender_id if `reply_to_id` is set (one additional join or subquery).

Return: `{ users: Array<{ id, username, email, avatar_url }> }`.

If `q` is empty or less than 2 characters, return empty array (prevent full-table dump).

Request body:
```typescript
{
  type: 'direct' | 'group';
  name?: string;           // required for group, ignored for direct
  participant_ids: string[]; // other users to add (creator added automatically)
}
```

**Direct conversation flow (D-19 — idempotent):**
1. Validate: exactly 1 participant_id (the other user)
2. In a Drizzle transaction with advisory lock (RESEARCH.md Pattern 8):
   ```typescript
   import { createHash } from 'crypto';
   const lockKey = BigInt(`0x${createHash('md5').update([userId, targetUserId].sort().join(':')).digest('hex').slice(0, 16)}`);
   await tx.execute(sql`SELECT pg_advisory_xact_lock(${lockKey})`);
   ```
3. Check if direct conversation already exists between the two users (join conversation_participants twice)
4. If exists: return 200 with existing conversation
5. If not: INSERT into conversations + INSERT two rows into conversation_participants (both `is_admin: false`)

**Group conversation flow (D-18):**
1. Validate: `name` required, `participant_ids.length >= 1`
2. INSERT into conversations with `type: 'group'`, `name`
3. INSERT creator into conversation_participants with `is_admin: true, can_edit_messages: true`
4. INSERT all participant_ids into conversation_participants with `is_admin: false, can_edit_messages: false`
5. Return 201 with new conversation

**After creation (D-38):** Broadcast `{ type: 'conversation:new', payload: conversation }` to all participants via registry broadcast.

Return the full conversation object plus participants array (same shape as GET /api/conversations items).

HTTP status: 201 for new creation, 200 for returning existing direct conversation.
