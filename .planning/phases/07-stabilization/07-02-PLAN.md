  <action>
Rewrite `.vps-test-ws.mjs` as a structured E2E regression test with assertion-based pass/fail. Keep the same execution model (runs inside api container via `docker exec mmess-api-1 node /app/.vps-test-ws.mjs`).

**Structure:**
- Keep existing helpers: `loginAs`, `getConversations`, `createDM`, `me`, `connectWS`, `sleep`.
- Add an `assert(condition, label)` helper that throws on failure and logs `[PASS]` on success.
- Add a `waitForType(ws, type, timeoutMs = 3000)` helper that returns a Promise resolving to the first message matching `type` received on `ws`, or rejects after timeout.
- Add a `collectMessages(ws)` helper that pushes all incoming parsed messages into an array accessible by the test — the existing `ws.on('message')` logging stays but also appends to an array.

**Test sections (run sequentially in one async IIFE):**

1. **Auth test:**
   - Login as admin@chatboris.local / AdminPass123! — assert cookie returned
   - Login as tester@chatboris.local / TesterPass123! — assert cookie returned
   - GET /auth/me for both — assert `id` and `username` present

2. **WS connect test:**
   - Connect both as WS — assert both get `open` event
   - Wait 500ms for connection stability

3. **Message send/receive test:**
   - Admin sends `message:send` with `content: 'e2e-test-' + Date.now()` to the DM
   - Assert admin receives `ack` with matching `id` and `payload.message.content`
   - Assert admin receives `message:delivered` with `payload.message_id` (because tester socket is OPEN)
   - Assert tester receives `message:new` with `payload.message.content` matching

4. **Read receipt test:**
   - Tester sends `read:mark` with the message_id from step 3
   - Assert admin receives `read:by` with `payload.message_id` (SINGULAR — D-07 verified), `payload.user_id` equal to tester's id, and `payload.read_at` present
   - Assert tester ALSO receives `read:by` (multi-session sync — tester's socket is not excluded, only source socket is)

5. **Reaction test:**
   - Tester sends `reaction:add` with emoji '👍' on the message from step 3
   - Assert admin receives `reaction:added` with `payload.emoji === '👍'` and `payload.user_id === tester.id`
   - Assert tester also receives `reaction:added` (reactions use plain broadcast, no exclusion)

6. **Typing test:**
   - Admin sends `typing:start` with `conversation_id`
   - Assert tester receives `typing:user` with `payload.typers` containing admin's userId
   - Admin sends `typing:stop`
   - Assert tester receives `typing:user` with empty `payload.typers` array

7. **Presence test:**
   - Close tester WS connection
   - Wait 4000ms (3s offline grace + 1s buffer from server presence.ts)
   - Assert admin receives `presence:update` with `payload.user_id === tester.id` and `payload.online === false`

**Exit behavior:**
- On any assertion failure: log `[FAIL] {label}: {details}`, close all sockets, `process.exit(1)`
- On all pass: log `\n=== ALL TESTS PASSED ===`, close all sockets, `process.exit(0)`
- 30-second global timeout: if tests hang, `process.exit(2)` with "TIMEOUT"

**Important:** Log every received WS frame (as the existing script does) for debugging. Each test section should be wrapped in a console.log header like `\n--- TEST: Message Send/Receive ---`.
