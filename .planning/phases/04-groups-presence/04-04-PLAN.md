REST endpoints from Plan 04-01:
- PATCH  /api/conversations/:id              Body: { name: string }
- POST   /api/conversations/:id/participants  Body: { user_ids: string[] }
- DELETE /api/conversations/:id/participants/:user_id
- PATCH  /api/conversations/:id/participants/:user_id  Body: { can_edit_messages: boolean }
- DELETE /api/conversations/:id/me

All return 200/204 or error. On success, server broadcasts conversation:updated which
automatically updates the conversation in state via CONVERSATION_UPDATED (Plan 04-03).
So after a successful mutation, re-read `conversation` from state.conversations — it
will already be updated.
