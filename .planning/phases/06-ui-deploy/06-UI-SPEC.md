## Theme System Contract

### Implementation (from CONTEXT.md D-01 through D-08)

| Decision | Value |
|----------|-------|
| States | `light` \| `dark` \| `system` |
| Default | `system` |
| Persistence | `localStorage` key `mmess.theme` |
| DOM attribute | `data-theme="light"` or `data-theme="dark"` on `<html>` element |
| System resolution | `matchMedia('(prefers-color-scheme: dark)')` — live via `addEventListener('change', ...)` |
| Flash prevention | Inline pre-hydration script in `<head>` (before React) |

### Pre-hydration script (exact text, minified, for `client/index.html`)

```html
<script>(function(){var t=localStorage.getItem('mmess.theme')||'system';var r=t==='system'?(matchMedia('(prefers-color-scheme:dark)').matches?'dark':'light'):t;document.documentElement.dataset.theme=r;})();</script>
```

Place this as the **first child of `<head>`**, before any other scripts or stylesheets.

### `index.html` changes (complete head section after Phase 6)

```html
<head>
  <script>(function(){var t=localStorage.getItem('mmess.theme')||'system';var r=t==='system'?(matchMedia('(prefers-color-scheme:dark)').matches?'dark':'light'):t;document.documentElement.dataset.theme=r;})();</script>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
  <meta name="theme-color" content="#0b57d0" />
  <link rel="manifest" href="/manifest.json" />
  <title>mmess</title>
</head>
```

Note: `viewport-fit=cover` is required for iOS safe-area-inset-* env() values to work (D-16). The `theme-color` meta uses the light-mode accent value (#0b57d0); this is acceptable for v1 — no dynamic `theme-color` update on toggle.

### Filter logic (client-side, D-10 through D-15)

State: `const [searchQuery, setSearchQuery] = useState('')` — local to `ConversationList`, not in `ChatContext`.

Derived filtered list (computed inline, not memoized unless profiling reveals a need):

```typescript
const filtered = searchQuery.trim() === ''
  ? state.conversations
  : state.conversations.filter(conv => {
      const q = searchQuery.toLowerCase();
      if (conv.name.toLowerCase().includes(q)) return true;
      return conv.participants.some(p => p.username.toLowerCase().includes(q));
    });
```

Pass `filtered` to the map in the `.list` div instead of `state.conversations`.

- Search scope: `conversation.name` (case-insensitive substring) OR any `participant.username` (case-insensitive substring)
- No server calls — fully client-side (D-10)
- No result highlighting (D-15)
- Clear on conversation selection: do NOT auto-clear search when user taps a conversation; user clears manually via × or by deleting text

## Interaction Contracts

### Theme toggle interaction

- Clicking any of the three buttons immediately applies the theme (no confirmation, no delay)
- Active button reflects current stored state, not just the resolved theme (if `system` is stored and OS is dark, the monitor button is active — not the moon button)
- The `system` state means "follow OS"; the resolved dark/light class is applied to `<html>` but the toggle shows `system` as active

### Search interaction

- Typing in the search input immediately filters the conversation list (no debounce — client-side filter is synchronous and fast for tens of conversations)
- × button clears query and refocuses the input
- `Ctrl+K` / `Cmd+K` focuses input; if input is already focused and query is non-empty, does not clear (user must use ×)
- Escape while search input is focused: clears query if non-empty; if already empty, blurs the input
- `aria-live="polite"` on a visually hidden element that announces result count: `"[N] conversations"` after each filter change (screen reader feedback without visual disruption)

### Mobile safe-area interaction

- Safe-area padding applies only when `env(safe-area-inset-*)` resolves to a non-zero value (notch/Dynamic Island devices)
- Sidebar footer with ThemeToggle does not overlap the iOS home indicator
- No horizontal safe-area insets needed for the current layout (sidebar + pane are not edge-to-edge horizontally in the way that requires left/right insets except for full-bleed backgrounds)

### Touch target enforcement pass (D-19)

For all interactive elements in all components, verify at least 44×44px effective touch target. Known cases to check during execution:

| Element | Current known size | Fix if needed |
|---------|--------------------|---------------|
| Theme toggle buttons | 36×36px | Add `padding: 4px` to achieve 44×44 effective, or accept 36px (thumb area, not primary interaction) |
| Search × button | 16×16 icon | Wrap in `<button>` with `min-width: 44px; min-height: 44px; display: flex; align-items: center; justify-content: center` |
| Magnifier (non-interactive) | 16px | Not interactive — no fix needed |
| ConversationItem row | full sidebar width × height | Already meets target from Phase 3 |
| Send button | 44px from Phase 3 | Verify unchanged |
| Paperclip button | 40px from Phase 5 | Raise to 44px during this pass |

**Decision on theme toggle buttons:** Accept 36×36px for the toggle buttons. They are a preference control accessed infrequently, not a primary interaction path. The touch target is still reasonable at 36px and expanding them would break the segmented-control aesthetic.

### Docker Compose healthchecks (D-26)

Add to `docker-compose.yml` for each service:

```yaml
postgres:
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U $$POSTGRES_USER"]
    interval: 10s
    timeout: 5s
    retries: 5
    start_period: 10s

api:
  healthcheck:
    test: ["CMD-SHELL", "node -e \"require('http').get('http://localhost:3000/health',r=>process.exit(r.statusCode===200?0:1)).on('error',()=>process.exit(1))\""]
    interval: 15s
    timeout: 5s
    retries: 3
    start_period: 30s
  depends_on:
    postgres:
      condition: service_healthy

caddy:
  healthcheck:
    test: ["CMD", "caddy", "version"]
    interval: 30s
    timeout: 5s
    retries: 3
```

The `api` healthcheck uses Node's built-in `http` module — no `curl` or `wget` needed in the Alpine image. The `/health` endpoint exists from Phase 1.

### Backup script behavior (`scripts/backup.sh`)

- Dumps PostgreSQL to `backups/db-$(date +%F).sql.gz` via `docker compose exec -T postgres pg_dump ...`
- Archives uploads volume to `backups/uploads-$(date +%F).tar.gz`
- Deletes all but the 7 most recent files of each type in `backups/`
- Uses `bash` (not `sh`) for array support
- Is idempotent: running twice on the same date overwrites the existing files
